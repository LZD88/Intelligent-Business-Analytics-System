# identity-access Specification

## Purpose

为多人使用建立经过认证的身份与资源授权，区分管理、审核和分析职责，并隔离租户、个人历史及业务数据权限，避免客户端自报身份成为权限或审计依据。

## Requirements

### Requirement: 身份与角色授权
系统 SHALL 支持首个管理员初始化、密码登录、注销、过期会话和用户管理；密码 MUST 单向派生存储，会话 MUST 可撤销。管理员、审核者、分析者 SHALL 按权限访问管理接口。

#### Scenario: 匿名或越权访问
- **WHEN** 未登录用户访问受保护 API 或分析者发布指标
- **THEN** 分别返回未认证或无权限，不执行变更

### Requirement: 租户与历史隔离
系统 SHALL 从已认证身份确定租户，隔离指标目录、数据源和反馈，个人历史默认只对其所有者可见，所有审核记录 SHALL 使用真实身份。

#### Scenario: 猜测历史 ID
- **WHEN** 另一用户或租户请求查询 ID 的结果、事件、证据或续跑
- **THEN** 系统拒绝且不泄露内容
