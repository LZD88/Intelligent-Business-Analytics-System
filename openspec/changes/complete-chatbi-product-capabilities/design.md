# Design

## Context

参见 proposal.md。现有 FastAPI、MySQL 安全执行器、SQLite 控制库和 Chroma 均保留。新增功能必须兼容现有本地模式与教学脚本，不复制或打印现有凭据。

## Goals / Non-Goals

完成七项用户授权的能力及可复核交付。真实业务接入以现有 MySQL 技术栈为范围；不同数据库方言不在本轮隐含扩展。真实业务效果不能由技术测试替代。

## Decisions

1. 身份和控制资源使用 SQLite 事务、PBKDF2 密码及随机会话令牌 Hash；启用认证后所有资源由服务端身份确定。保留显式本地兼容模式，启动器启用认证。
2. 数据源凭据使用独立受保护密钥加密，元数据通过受控 MySQL 管理通道发现，业务查询仍只能接收安全层产物。指标控制库按租户及数据源分区。
3. 每个并发查询创建独立服务快照、用量和用户上下文；不再在全局锁内执行外部模型。同机使用 SQLite 事务租约；跨主机可配置 PostgreSQL 中心控制库，同时共享账号、目录、历史、队列和断点，使用事务锁与租约 fencing。各节点部署同一凭据密钥及稳定控制库文件名，不在网络磁盘上共享 SQLite。
4. DAG 调度使用有界线程池并传播 ContextVar，等待依赖后调度；核心失败设置分支取消信号，外部调用仍遵循超时。共享历史和断点由事务保护。
5. 纠错案例由审核者安全执行并保存标准结果，发布后按租户、数据源与口径版本召回；回归集导出保留独立标准 SQL。
6. 报告正文采用受控数值及陈述检查，不声称证明所有业务判断；失败进入现有有界修复和可信模板路径。
7. 使用独立标准 SQL 覆盖全部初始指标，增加复杂题；真实评测只在最终代码冻结后执行。分批提交功能分支，最终整合并执行远端 CI。

## Risks / Trade-offs

- 共享 SQLite 只支持同机共享磁盘的多进程协调 → 明确部署拓扑，使用租约和事务测试，不声称跨主机共享文件安全。
- 外部模型输出波动 → 保留完整失败记录，不弱化验收门槛。
- 数据源变更和口径漂移 → 查询、断点及案例绑定数据源、权限和目录指纹。
- 文本核验存在表达边界 → 明确机器检查与人工业务审核状态，禁止收益保证。

## Migration Plan

先备份控制库，所有表增量迁移；保留原演示库和历史。新增配置具备兼容默认值，实际本机使用启动器启用登录。验证后提交、跑 CI 并归档规格；回退代码前保留新增控制库备份。
