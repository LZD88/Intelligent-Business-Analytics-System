# ChatBI 多用户与业务接入操作说明

## 首次使用

在项目目录运行 `scripts/chatbi.ps1 start`，访问 `http://127.0.0.1:8000/login`。首次页面只允许本机初始化管理员，密码至少 12 位。初始化完成后登录；本轮交付不预设生产管理员或通用密码。原本机历史在初始化时归属首位管理员。

管理入口位于左侧「账号与数据源」。分析员可以问数和提交纠错；审核员可以审核指标、审核其他人的纠错；管理员管理本租户用户、数据源和授权。首位管理员可为其他租户创建管理员。其他租户不自动获得演示业务库，需接入自己的数据源。停用账号或改变角色会撤销会话。

历史、事件、证据、下钻、取消和续跑均检查所有者、租户、数据源及权限版本。指标与发布案例在同租户同数据源内共享；个人查询历史不向同租户其他用户公开。授权、连接、口径改变后，应重新查询，旧任务与案例不能继续沿用旧权限。

## 接入 MySQL

1. 准备只授予 `SELECT`、可选 `SHOW VIEW` 的独立账号。应用会读取实际授权，发现写入、管理权限、角色授权等未知语法时拒绝接入。
2. 管理页展开「接入 MySQL 数据源」，填写连接信息并读取结构。只选择需要问数的表和字段，再保存。
3. 为分析员、审核员授权具体数据源，可配置表子集、行过滤和敏感字段。示例：`{"tables":["sales_orders"],"row_filters":[{"table":"sales_orders","column":"region","value":"华东"}],"sensitive_fields":["customer_id"]}`。敏感字段禁止参与用户 SQL，防止通过别名或星号读取。
4. 在工作台左侧切换数据源。新源从空指标目录开始，在「指标管理」建立并发布真实业务口径。演示问题只在演示源展示，表字段数随源切换。
5. 修改连接需重新输入密码、读取结构并明确选择白名单。停用数据源会阻止后续访问。跨库限定名、系统库和白名单外字段不能进入查询。

结构发现同时读取真实字段类型，只将白名单字段的类型提供给规划与执行 Agent；整数 ID 保持整数契约，不能因为字段是标识符就转为文本。连接升级前已保存的数据源需重新读取结构并保存，才能补齐类型元数据。

密码由 Fernet 加密保存于控制库，独立密钥位于控制库同名 `.key` 文件。API 不返回密文或密码。远程 MySQL 应配置可信 CA 路径，启用证书与主机名校验。元数据发现仅是技术接入，仍需业务负责人确认含义、时区、币种及关联粒度。

## 反馈如何生效

在结果中记录反馈后，进入「反馈案例库」，填写本人原查询 ID、问题、修正 SQL，以及独立核对的 `{"columns":[...],"rows":[...]}` 标准结果。提交时执行安全检查和精确结果比对，结果截断不能作为标准答案。

草稿由另一位审核员或管理员发布，不能自审。发布会重新执行，并核对目录版本；只要结果变化或口径过期，就拒绝发布。已发布案例只对同租户、同数据源、当前口径的规范化同问题召回，作为不可信示例数据加入 SQL Prompt，仍需经过安全执行层。当前采用精确问题匹配，避免相似问题误套口径。

「导出已发布回归案例」生成包含标准 SQL 和独立预期结果的 JSON，可交给 `Evaluator.evaluate_all(cases, sql_generator)` 执行回归。数据更新后需复核预期结果、重新提交审核；不要把标准结果中的业务数据上传到公开仓库。

## 报告核验边界

总结 Agent 输出必须绑定成功步骤中的真实单元格。正文数字检查支持直接证据、引用数值的差额与比例、明确金额单位的显示精度、显式数值比较方向；无据因果和收益保证会触发修复，仍不合格则回退确定性模板。界面和 Markdown 均显示核验状态。

摘要和局限中的返回行数只使用完整步骤的实际行数；行数不能支持金额。用户明确给定的阈值只允许作为阈值或比较对象，不能充当业务结果。对 NULL 的“不能填零”提示不会被误当成实际零值。正文核验失败时给模型提供具体定位片段修复，运行日志仍不记录业务数值。

这些机械检查不能证明隐含语义、业务因果、比较口径合理性或建议能产生实际收益。分析建议仍需人工业务审核。数据截断、步骤降级和缺少基期必须保留披露，不能当作完整业务结论。

## 配置与部署拓扑

默认 `AUTH_ENABLED=true`。生产 HTTPS 入口设置 `AUTH_COOKIE_SECURE=true`；保持同源反向代理，禁止浏览器绕过认证直连内部控制库。`AUTH_SESSION_SECONDS` 默认 28800。仅在隔离开发测试中显式设置 `AUTH_ENABLED=false`。

启动器默认 `QUERY_WORKERS=4`、`COMPLEX_PARALLEL_WORKERS=2`、`SHARED_QUEUE_ENABLED=true`；直接使用 Settings 的默认值为单 Worker、串行分支。可用环境变量覆盖。每个查询保留独立服务、目录、用户权限与模型用量；分支线程传播查询上下文。取消是协作式，当前供应商调用可能需要等待超时返回。

同机多个 API 进程共享本地 SQLite 控制、历史、指标及 catalogs 目录，必须使用一致的绝对路径，启用共享队列。每个任务有原子领取、定时续租和写入 fencing。租约过期进入中断或保留原断点，不自动重放不确定外部调用。`QUERY_JOB_CAPACITY` 限制全局待执行任务，`QUEUE_LEASE_SECONDS` 默认 45。

跨主机使用 PostgreSQL 中心控制库：在进程真实环境中设置 `CONTROL_DATABASE_URL`，例如 `postgresql://<user>:<password>@<host>/<database>?sslmode=verify-full`。该连接项由控制连接适配器读取，**只放 `.env` 不会导出给适配器**，应通过系统服务/容器 Secret 注入。此库只存身份、授权、目录、历史、队列及断点；业务查询仍在 MySQL。各节点配置相同的控制/历史/指标文件名；适配器按稳定文件名确定独立 schema，各租户源 catalog 使用稳定散列名。各节点须安全预置相同凭据密钥，使用相同代码、角色模型和权限配置，并能访问相同 MySQL。Chroma 演示索引可共享服务；自定义源使用其授权结构。

不要在 NFS/SMB 上共享 SQLite。PostgreSQL 控制事务使用每 store 的 advisory lock，保证排他领取及迁移一致；这是中小规模可靠协调方案，吞吐上限仍受控制事务锁与外部模型速率约束。连接 PostgreSQL 后不会自动导入旧 SQLite 数据，迁移前应备份并进行单独数据迁移核对。

## 备份和恢复

先停止**所有** API/Worker 写入，等待正在运行的调用退出。保留服务版本和配置指纹，暂停发布指标和调整授权。业务 MySQL 使用独立 DBA 备份流程，向量索引可按目录重建。

SQLite 模式需备份控制库、历史库、指标库、整个 `catalogs/` 目录及控制库同名 `.key`。在线备份使用 Python `sqlite3.Connection.backup`，不能只复制仍在写入的主文件而漏掉 WAL。停服后普通文件副本也应保留同一批次全部文件。所有备份放在受限目录或加密存储，密钥与数据分开保管。

PostgreSQL 模式先在维护窗口对控制数据库执行 `pg_dump -Fc -d <service>`，使用 `.pgpass`/服务配置，勿把口令写到命令行或脚本；同时另行备份各节点共用 `.key`。恢复到新的空数据库执行 `pg_restore --exit-on-error -d <new-service> <backup>`，恢复后对各 `chatbi_*` schema 的表、行数和真实目录版本逐一比对，再切换连接。中心库授权账号需要建 schema、表和运行事务；业务只读账号不要复用该身份。

恢复先在隔离目录/数据库演练，不覆盖原库。SQLite 使用 `PRAGMA integrity_check` 和表计数核对；PostgreSQL 用相同查询核对用户、来源、发布指标、历史及断点。验证使用原密钥可解密已存连接，完成登录、只读查询和断点状态核对后再切换服务。恢复会包含备份时的会话，可通过注销/账号停用重新登录处理需撤销的会话。

Windows 启动器的 `launcher-secrets.clixml` 使用当前 Windows 用户 DPAPI，跨机器不能直接解密；新机器应重新安全输入模型凭据。控制库密钥不能遗失，否则无法恢复数据源密码，需要重新录入连接。备份、密钥、`.env`、运行日志和业务结果均不提交 Git。

## 验证与发布

后端 `pytest`、前端 `node --test tests/*.test.mjs`、`mypy chatbi`、密钥扫描和启动器合约分别检查。GitHub CI 另起真实 PostgreSQL 验证中心控制库、跨进程任务；集成工作流另起 MySQL/Chroma 验证标准 SQL、授权源接入和故障恢复。

完整模型验收由 `scripts/chatbi.ps1 evaluate` 执行，覆盖 61 指标的独立标准 SQL、同比环比、多层关联、空结果、零分母及对话路由。只有代码、模型、目录及题库身份一致，报告才有效。中断可用 `-ResumeEvaluation`，变化后必须重跑。每轮失败报告也保留，禁止通过换标准答案或隐藏失败题使门槛通过。
