## 实现

- 真实题库由 11 题扩展为 121 题：102 道 SQL 结果题、3 道复杂多阶段题、16 道问候/澄清/追问题。新增题族覆盖 46 个指标，仍不是全部 61 个指标的完整验收。
- 所有 109 条标准 SQL（含复杂和追问）通过本机只读 MySQL 与 AST 检查。数字结果统一比较精度，保留空值和零的区别，不将百分比 75 与小数 0.75 当作相同结果。
- 评测逐题原子保存，支持相同代码、配置、目录和题库下断点续跑；包含 P50/P95、阶段耗时、各角色及聊天/意图/Embedding 的 Token 统计。
- 模型指纹涵盖接口、角色模型、推理开关、参数、执行策略、数据源位置、指标版本；不保存密钥或 URL 查询参数。看板识别旧报告、配置变化和未完成评测。
- SQL、规划、执行、校验、总结模型可分别配置，默认继承主模型，共用兼容接口及凭据。厂商推理参数为显式选项，默认 auto 不发送该扩展。
- 数据库查询耗时与模型复核/修复耗时分开；每次查询返回角色用量。前端看板脚本增加版本标识，解决旧脚本缓存。
- 修正中文相对日期“最近三个月”等被误判为缺少时间范围的问题。
- 总结修复会携带上一次结构化草稿和具体对象绑定错误，要求逐字复制真实维度与三项索引。对象伪造、缺少数值证据等仍被拒绝，保留有界修复及模板回退。
- 启用真实意图路由时，回退规则即使得到正确 SQL 也不能取得完整模型验收通过。本地问候识别属于正常路径。
- 语义复核使用 AST 明确 `NOT (x IS NULL)` 的括号，避免将合法空值判断误判为优先级错误；执行 SQL 不变，确定的业务错误仍进入修复或拒绝。
- 查询在分类后失败时保留实际 `intent_source`，避免把 SQL/业务校验失败误标为千问服务回退；澄清也必须有实际模型分类来源。
- 规划修复携带上一份无效草稿及具体契约错误，禁止通过删除维度、合并单步或丢弃结果绑定规避错误；显式要求“上游结果”的任务必须声明跨步骤输入绑定。
